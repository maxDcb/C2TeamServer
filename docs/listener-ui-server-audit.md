# Audit de la gestion des listeners entre GUI et TeamServer — 25 octobre 2026

Périmètre : création, liste, arrêt et réconciliation des listeners primaires et enfants, depuis `C2Client` jusqu'aux services gRPC du TeamServer et retour. Revue statique du commit `40e1885` ; tests client ciblés exécutés sous WSL. Aucun cycle complet avec serveur et beacon réels n'a été exécuté pour cette passe.

## Parcours observé

| Étape | Comportement actuel | Source |
| --- | --- | --- |
| Création dans la GUI | Le formulaire valide type, adresse/domaine, port ou projet/jeton, ainsi que les conflits de ports TCP connus dans la table locale. Il émet les trois champs et se ferme ; le panneau construit ensuite le `Listener` Protobuf et appelle `AddListener` directement. | [Formulaire et panneau](../C2Client/C2Client/ListenerPanel.py) |
| Création côté serveur | Après contrôle du jeton, le service refuse GitHub si désactivé, détecte doublons et conflits TCP, initialise le listener, l'ajoute à la collection en mémoire, puis renvoie `OperationAck` (`OK`/`KO`, message). | [RPC](../teamServer/teamServer/TeamServer.cpp), [service](../teamServer/teamServer/TeamServerListenerSessionService.cpp), [contrat](../protocol/TeamServerApi.proto) |
| Retour d'état | Un worker interroge `ListListeners` toutes les 2 s par défaut, avec repli jusqu'à 15 s après erreur. Il remplace les lignes absentes, met à jour les présentes et ajoute les nouvelles ; le panneau conserve la sélection par hash complet. La liste des listeners enfants est dérivée des sessions de chaque listener primaire. | [Worker](../C2Client/C2Client/refresh_worker.py), [panneau](../C2Client/C2Client/ListenerPanel.py), [service](../teamServer/teamServer/TeamServerListenerSessionService.cpp) |
| Arrêt | La GUI envoie `ListenerSelector.listener_hash`. Le serveur retire immédiatement un listener primaire ; pour un listener enfant, il met une instruction d'arrêt en file vers le beacon et renvoie « stop requested ». La disparition de la ligne est constatée lors d'un `ListListeners` ultérieur. | [Panneau](../C2Client/C2Client/ListenerPanel.py), [service](../teamServer/teamServer/TeamServerListenerSessionService.cpp) |
| Redémarrage/reconnexion | Un échec de liste conserve temporairement la table locale et affiche un état d'erreur. Le prochain appel réussi peut réauthentifier le client, puis le panneau retire les anciennes lignes et ajoute celles de la nouvelle instance du serveur. | [gRPC](../C2Client/C2Client/grpcClient.py), [worker](../C2Client/C2Client/refresh_worker.py), [panneau](../C2Client/C2Client/ListenerPanel.py) |

## Constats

| Priorité | Constat et conséquence | Vérification ou correction attendue |
| --- | --- | --- |
| Haute | **Ajout et arrêt bloquent la GUI sur une RPC sans deadline.** Les boutons et le menu appellent `grpcClient.addListener`/`stopListener` sur le fil Qt ; ces deux méthodes n'ont pas de `timeout`, contrairement à `ListListeners` (3 s). Une indisponibilité réseau peut laisser la fenêtre figée ; une exception gRPC remonte sans traitement local dans ces actions. | Déporter les mutations vers un worker, fixer une deadline, garder l'action en attente jusqu'à l'ACK, puis gérer explicitement l'erreur et l'état du formulaire. |
| Haute | **La validation métier dépend du client GUI.** `validate_listener_fields` contrôle IP, domaine, projet et plage de ports côté Python, mais `TeamServerListenerSessionService::addListener` ne répète pas ces règles avant d'instancier le listener. Un autre client gRPC peut fournir des valeurs que la GUI aurait refusées ; l'échec est alors délégué aux bibliothèques ou signalé de façon générique. | Valider type, champs requis et plage des ports côté serveur, avec un `KO` explicite pour chaque refus ; garder la validation GUI comme aide à la saisie. |
| Moyenne | **La table montre « enregistré » comme « actif ».** `streamListeners` énumère la collection en mémoire sans consulter `isRunning()` ; le message `Listener` n'a pas de champ d'état. Si un worker de listener s'arrête après un `AddListener` réussi, la GUI peut continuer à le présenter comme disponible. | Exposer un état de cycle de vie, traiter les listeners défaillants et vérifier que la table reflète un arrêt inattendu. |
| Moyenne | **L'ACK ne donne pas l'identifiant créé et l'arrêt enfant n'est pas confirmé.** `OperationAck` ne contient que statut/message ; la GUI attend le prochain polling pour découvrir le hash. Pour un enfant, « stop requested » signifie seulement que la tâche a été mise en file, tandis que la ligne reste jusqu'au changement d'état du beacon. | Distinguer « demandé », « actif », « arrêt en cours », « arrêté/échec » ; corréler l'ACK de création à un identifiant et prévoir une échéance de confirmation pour l'enfant. |
| Moyenne | **Le menu contextuel arrête par préfixe de huit caractères.** Il lit l'ID abrégé affiché dans la cellule puis parcourt tous les listeners dont le hash commence par ce préfixe. Deux hashes partageant ces huit caractères déclenchent deux arrêts pour un seul clic. Le bouton Stop utilise déjà le hash complet. | Conserver le hash complet dans les données de la ligne ou sélectionner l'objet de la ligne cliquée ; ajouter un test avec collision de préfixe. |
| Moyenne | **Les hooks interprètent le diff local comme événement de cycle de vie.** Le premier snapshot d'un client fraîchement ouvert émet `OnListenerStart` pour les listeners déjà actifs ; après reconnexion, les suppressions et ajouts de la table émettent `OnListenerStop`/`OnListenerStart`. Ces signaux décrivent une découverte locale, pas nécessairement une transition réelle côté serveur. | Séparer synchronisation initiale et événements de cycle de vie, ou documenter cette sémantique et tester les effets des hooks au redémarrage. |
| Conditionnelle | **GitHub figure dans le formulaire alors que le build standard le refuse.** `C2_ENABLE_GITHUB_TRANSPORT` vaut `OFF` par défaut. Si le transport est activé, `ListListeners` renvoie le jeton complet et le serveur le journalise à la création ; masquer seulement la valeur dans la table GUI ne réduit pas cette exposition. | Ne proposer que les types disponibles et ne jamais retourner ni journaliser le jeton complet. Garder GitHub désactivé tant que son [audit propre](github-transport-audit.md) reste ouvert. |

## Couverture et prochaine preuve

`QT_QPA_PLATFORM=offscreen C2Client/.venv/bin/python -m pytest -q C2Client/tests/test_listener_panel.py C2Client/tests/test_grpc_client.py` : **39 tests réussis**. Les tests couvrent notamment la saisie, les conflits de ports, le rendu des listeners enfants, la suppression de lignes absentes, la réauthentification de `ListListeners` et l'absence de rejeu d'une mutation `UNAVAILABLE`. Les tests C++ du service vérifient l'émission primaire/enfant, le conflit TCP et le refus de GitHub désactivé.

Preuve encore nécessaire : cycle GUI ↔ vrai serveur pour créer, lister, arrêter et recréer HTTP/HTTPS, TCP et DNS ; arrêt d'un listener enfant avec beacon ; indisponibilité pendant chaque action ; redémarrage serveur avec anciennes lignes visibles ; erreur après ACK mais avant le polling suivant. Les tests existants ne prouvent pas encore ces transitions de bout en bout.
